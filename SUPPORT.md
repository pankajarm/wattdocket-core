# Getting help

Start with the [README](README.md) for installation and local launch, [data provenance](DATA-PROVENANCE.md) for evidence sources, and [hosting guidance](docs/DEPLOYMENT.md) for running your own public instance.

Search [existing issues](https://github.com/pankajarm/wattdocket-core/issues). If the problem has not been reported, [open an issue](https://github.com/pankajarm/wattdocket-core/issues/new/choose) and include:

- Your operating system, Node.js and Python versions, and repository commit.
- The command or page that failed, the error text, and the steps needed to reproduce it.
- For data problems, the record or source URL, reporting period, and expected interpretation.

Remove API keys, authentication tokens, personal information, and private hostnames from logs and screenshots. Use the [security reporting process](SECURITY.md) for vulnerabilities.

Support is provided through repository issues as maintainer time permits. There is no paid support agreement or response-time guarantee associated with this repository.
